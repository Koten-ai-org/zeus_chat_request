Better, worse, and the score

The blue Versus column is the guess for base-8-prototype-1 against base-7.2 on the Target API column. It does not score which prose answer was nicer. A different verb that still returns rows is not a hit. The same words are used as the measured report so the future page can be laid on top of this one.

  • better: base-8-prototype-1 called the target API and base-7.2 did not.
  • worse: base-7.2 called the target API and base-8-prototype-1 did not. On “Find hoppy citrus beers” the target is search hybrid. That row is worse when base-7.2 calls search hybrid and base-8-prototype-1 calls search fts, find, or set, even when both sides are HTTP 200 and both returned beers.
  • both hit: both packs met the target.
  • both missed: neither pack met the target.
  • not run: a model call is missing, so the row is left out of the score.
  • Orange: a pack cell ends on HTTP 400 or higher, so the row is re-tested later. Orange stays out of better and worse.

Both hit and both missed stay out of the better and worse counts. The score still counts them as same. When the question says rows are required, an empty Zeus result is not met. pipeline means a pipeline ran.
