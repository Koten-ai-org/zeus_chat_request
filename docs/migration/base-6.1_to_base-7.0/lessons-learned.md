# Lessons: base-6.1 → base-7.0

Prompt sentences added after the numbered cut, and why each one is worth its characters, are in [PROMPT_SENTENCES.md](PROMPT_SENTENCES.md). Read that before adding another sentence.

## What worked

- **New folder, then a numbered cut.** `base-7.x` stayed the working train. `base-7.0` is the snapshot. The next tweak scaffolds another id. It does not edit `base-7.0` in place.
- **Parent is base-6.1.** The base-6.2 prefix diet measured smaller and then regressed in use. This train adds the method on the fuller catalog.
- **`rail` is name plus binds.** No SQL string in the tool. The operator owns the statement. The model fills slots the SCOPE BRIEF already named.
- **Boolean and `one_of` stay generic.** The pack teaches the law. The entity map owns the spellings and injects them into MINI-SCHEMA at chat time. A tenant list does not belong in the shared JSON.
- **`verify_base_pack.py` and `diff_modes.py --fail-if-clone` before the PR.** Ten modes, none identical.

## What this release does not do

- Flip `CURRENT.json`. That pin stays base-1.
- Execute `rail`. The catalog can plan the call. The engine cannot run it yet.
- Mention `find` `offset`. The V2 mapper does not forward it.
- Call `embed(scope, text)`. ZE-406 and ZE-407 own that. This pack passes `query_text` through.
- Run `assemble_mode_prompts.py` on this pack. That script can pull the base-6.2 skinny back in.
